# Deploying LoadMatch (Render)

## 1. Backend → https://empty-trackload-api.onrender.com

1. Push the `loadmatch-backend` folder to a GitHub repo.
2. Render Dashboard → **New → Web Service** → pick the repo.
   (Or `render.yaml` is included — Render reads it automatically.)
3. Set env vars in the Render dashboard:
   - `JWT_SECRET`, `ADMIN_KEY` — already auto-generated by `render.yaml`; copy them somewhere safe.
   - `PAYSTACK_SECRET_KEY` / `PAYSTACK_PUBLIC_KEY` — from paystack.com → Settings → API Keys.
4. Add the disk (covered by `render.yaml`): 1 GB at `/var/data` so `db.json` survives deploys.
5. Deploy, then visit `https://empty-trackload-api.onrender.com/api/health` → `{"ok":true}`.
   Free tier cold start: first request after ~15 min idle takes ~50 s.

## 2. Frontend → https://empty-trackload.onrender.com (already deployed)

Redeploy with the current `loadmatch/` folder — `assets/js/main.js` now points
`API_BASE` at `https://empty-trackload-api.onrender.com`.

## 3. Paystack webhook

Dashboard → Settings → Webhooks:
- URL: `https://empty-trackload-api.onrender.com/api/payments/webhook`
- Events: `charge.success`

## 4. Smoke-test the live pair

```bash
BASE_URL=https://empty-trackload-api.onrender.com npm run smoke
```

## Notes

- Free Render services sleep on idle: the marketplace loads demo data when the
  API is unreachable, so the site never looks broken.
- Simulation mode stays active until you add Paystack keys — escrow then runs
  through real GHS charges via Paystack inline checkout.
